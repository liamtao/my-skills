# 说服型页面的概念

落地页、品牌页、发布页、展览页先有概念，再选骨架、写文案。本文件规定这类页面在 [轻路径](light-path.md) 第 1 步“方向”那一行要交的东西：一句概念、标题原文、主视觉描述，做整页前再交一张画面表。骨架从 [说服型骨架](direction-persuasion.md) 里选。

顺序固定：概念先定，标题随概念定，骨架在它之后选，其余文案在骨架之后写。骨架文件里说的“先定骨架再写文案”，指的是标题以外的文案。北极星从选中的概念推出，不另起一个。默认由主 Agent 自己定概念，不派子 Agent，不出图片批次；要加深时见文末。

## 概念是什么

一句话：把这个产品最想让人记住的主张，说成一个具体的画面。标题和主视觉从这一句里一起推出，讲的是同一件事；左边喊一句通用卖点、旁边摆一张普通的产品截图，两边各说各的，不算概念。

动手想概念前，先在笔记里**盘点 6–10 件只属于这个主体的具体事物**：数字产品或工具，写它真正读写的对象、核心操作前后的状态变化、关键指标和用户原本手边的旧工具；实体、空间或文化品牌，写它的名字本意、场所特征、题面里的硬数字和限制、原材料，以及它的世界里真实流转的凭据和单据。概念的画面、版块的载体和后文的找图关键词，都从这份清单里取。

写完概念后用一句填空做**同行替换检验**：
> 在这页上，**【盘点清单里的一件具体事物】** 变成了 **【首屏和整页的核心视觉、版块载体或交互装置】**。

三条检验，有一条不过就换一个概念，不靠加说明补救：

- 标题和主视觉分开看，各自不完整。主视觉就是文字本身的方向，这一条不适用。
- 合起来一读就懂。
- **换到同品类另一家产品上不成立**：把隔壁同行的名字代进上面的填空句，句子依然成立，说明想到的只是整个品类都能用的画面，回到盘点清单重选。

主视觉可以直接把产品处理的对象或交付的结果做成画面，也可以借一个受众一眼认得、和产品主张道理相通的事物来表达，首屏不必放完整的产品界面。借来的事物和它的画法，来源就是这句概念。概念只管标题、主视觉和各区块的画面；功能名、按钮、导航和价格用产品本身的说法。

**让容器和交互也顺着概念长出来。** 选定概念后，别让它只停在首屏的一张图上，到了下面又退回通用的网页线框：

1. **开放画布配一两处专属载体**：整页大部分版面让主视觉、大字和核心内容直接排在底色画布上，不把每一屏都封进有底色和边框的盒子里。只在最核心的 1–2 处做成呼应概念的专属载体，它的样子从盘点清单里取，是这个产品的世界里真实存在的东西，不从别的题材借。
2. **一处点题的真交互**：设计一处由概念直接推出来的可操作装置，用户改一个选择，画面、数据或价格当场跟着变；用业务真实数据驱动，手机上单手能操作。

## 把概念带到首屏以下

已经有覆盖整页的 UI 设计稿时，直接从稿里整理画面表；只有首屏图时不算。没有整页设计稿时，主 Agent 先列出这页还要回答的问题，再写画面表。

写整页代码前完成画面表，每屏一行：回答哪个问题、小标题原文、画面（这一屏最大的那样东西是什么，和首屏的图是什么关系）、图从哪来、产品事实落在哪。每一屏是首屏那个想法的下一句，不退回“三列小图标配标题”的通用模板；哪一屏确实只需要文字、对比表或几张具体的特性卡，就照实写。画面表放进设计说明；有方向卡时写进它的“页面结构”和“各区块的形式”，滚动分镜写进“动效”。

- 首屏以下是否配图由画面表决定，不为文字或表格区块凑图。单独制作成套素材时，需要新画面的屏不拿主图缩放充数；主图的局部至多用在一屏，结尾可以再用一次主图。
- 价格、功能对比这类必须是表的，表照常做，表头、底或分隔取自同一套素材。
- 产品实样占其中一屏，放进这套画面里，示例内容从概念里取，不另起一个题材。

整页做完后的逐屏对照按 [方向贯穿整页](direction-whole-page.md) 做，对照的是这张画面表。送评审时，把这句概念摘成一句写进交接的约束。

## 什么时候加深

下面的情况出现时，读 [概念的加深做法](concept-deep.md) 里对应的一节，其余时候不读：

| 情况 | 读哪一节 |
| --- | --- |
| 用户要更有辨识度的概念、对第一版概念不满意，或明确要比较几个方向 | “概念交给子 Agent 出”和“选择对外方向” |
| 同时做了几个首屏，要在没有用户参与时自己选一个 | “三秒检验” |
| 画面表里有区块怎么写都落回通用模板 | “首屏以下派子 Agent 补构思” |
| 以图为主视觉，需要主图和成套配图 | “整页的图做成一套” |
