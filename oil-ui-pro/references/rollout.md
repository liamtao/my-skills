# 从一页铺成一套

返回 [主入口](../SKILL.md)。代表性页面做完、方向也定了，除代表性页面外还要做三页以上时用这份文件。少于三页时，照主入口的步骤 3 继续做就行。

做多页时常见的失败是：第一页很好，后面越做越走样。导航到第五页换了位置，同一种按钮出现三种样子，后台套上了落地页的大标题。原因通常是每一页都在临时决定，而不是沿用已经定好的东西。这份文件把铺开拆成五步：画页面地图、补齐样板、提取共享部分、写规范并给用户过目、分批铺开并做一致性检查。前三步是后面的地基，做完之前不铺开。

## 页面地图

先在设计说明里交一张表，这次要做的每一页占一行：

| 页面 | 领域 | 从哪进来 → 去哪 | 样板 | 状态 |
| --- | --- | --- | --- | --- |

- **领域**按主入口的“选择领域”，看这一页实际在做什么。同一个产品里，官网、文档和控制台往往属于三个不同的领域。
- **从哪进来 → 去哪**写导航关系：从哪个导航项或按钮进来，主要动作做完以后去哪。登录前后用两套导航时，写明在哪一步切换。
- **样板**这一列，要么写“样板”，要么写沿用哪一页。每个出现的领域至少要有一张样板页；同一领域的其他页面沿用它。
- **状态**依次是：待做、做完、已核对。

全局导航（顶栏、侧栏、页脚）在表下面单独写一行：用哪个组件，每页怎样标出当前位置。

## 补齐样板页

页面地图里某个领域还没有样板页时，先把它做出来，再开始铺开。做法按那个领域的入口来。

新样板沿用已定方向的品牌资产和语义角色，只在领域本来就不同的地方拉开差别：信息密度、字号层级、动效多少。例如控制台沿用官网的主色和字体，但不沿用官网的首屏大标题和滚动叙事。各领域分别以什么为准，按 [设计规范文件](design-spec.md) 的“治理与沉淀”里“分领域写”一条。

## 从样板提取共享部分

开始铺开前，从样板页里提出本次铺开要共用的两样东西，不顺带整理和这次铺开无关的代码：

- **变量**：样板页里写死的色值、字号、间距、圆角和时长，收进项目共享的变量文件。已有变量的，直接改成引用。
- **组件**：在页面地图里出现在两页以上的东西，做成共享组件，包括全局导航、按钮、表单控件、卡片和列表行。只出现一次的先不提取。

项目已经有组件库或样式体系的，提取到它里面，不另建一套。纯静态页面没有组件机制、也不引入构建时，全局导航这类部件在各页保持同一段代码，改一处就同步改所有页。存量项目里怎样落到现有变量和组件上，按 [存量项目](existing-project.md#从源头修改) 的“从源头修改”。

## 写规范并给用户过目

提取完以后，写设计规范文件。规范文件写在哪、写什么，按 [设计规范文件](design-spec.md) 的“什么时候写”和“写什么、放在哪”。

本任务还没有确认点时，回复里交两样东西：页面地图、各领域样板页的截图，请用户过目后再开始铺开。这是铺开阶段唯一的停顿。真有要用户拍板的事，例如某个领域的样板拿不准，就在这条回复里直接问，不另开一轮。用户已经在本任务里确认过方案、选定过方向，说过“直接做”，或者无人值守时，不停下来等，页面地图和样板截图随交付一起给出。

## 分批铺开

每批做三到五页，一批做完先做一次一致性检查，再做下一批。

做每一页之前，先对照设计规范文件和共享组件，列出这一页用到哪些现有组件、还缺什么。缺的先补进共享组件，再在页面里使用，不在页面里就地另画一个。新补的组件加进规范文件的“可用组件”一节。

页面里的文案、数据和状态按这一页自己的真实任务来写，不从样板页复制占位内容。

## 一致性检查

每批做完，用 [工具](tools.md) 把这一批的页面截成桌面和手机两种标准视口，再按领域分组，用 `--stitch` 拼成一张，样板页放在第一张。对着拼图看下面几项：

- 全局导航的位置、高度，以及当前位置的标法；
- 页面标题的层级和到页边的距离；
- 主按钮的样子，一屏里有几个；
- 同一种对象（卡片、列表行、表单）是不是长成一样；
- 页边距、栏宽和区块之间的间距；
- 窄屏下导航怎么收起。

再搜一遍这批页面的代码，找出没有引用变量、直接写死的色值和字号。找到的偏差在变量或共享组件里改，不在单页上打补丁。确实需要破例的，写进交付说明，问用户要不要改规范。都核对过的页面，在页面地图里标成“已核对”。

## 多个子 Agent 并行

宿主能派子 Agent、而且页面能分成两组以上时，才并行。否则一页一页按顺序做。

- **派发之前，主 Agent 先做完这些**：页面地图、共享变量、共享组件、全局导航和规范文件。这些都是共享文件，派发以后只有主 Agent 能改。
- **怎样分组**：按样板分，沿用同一张样板的页面交给同一个子 Agent。每个子 Agent 只写自己负责的页面文件。
- **派发时给什么**：页面地图里它负责的那几行、规范文件的路径、样板页路径、共享组件清单、禁止修改的共享文件清单，以及这几页各自的真实任务和内容。
- **要它交回什么**：页面文件、每页桌面和手机两种标准视口的截图、缺的组件（写明用在哪、需要哪些状态），以及和规范对不上、不得不破例的地方。
- **缺组件时**：子 Agent 先在自己的页面里用最接近的现有组件占位，把需求写进交回内容里。不在页面里另画一个，也不改共享文件。主 Agent 汇总以后统一补进共享组件，再把占位换掉。
- **全部交回以后**：主 Agent 补齐组件，对所有页面做一次一致性检查，再交付。
