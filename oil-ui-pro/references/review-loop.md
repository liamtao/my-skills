# 评审循环与扩展派发

主 Agent 专用，是 [视觉评审派发协议](visual-review.md) 的补充。视觉评审的交接清单和反馈处理照那份文件执行；开放式 UX 走查按下方专段，其他评审轮次和类型按本文件。各种评审的标准在 [评审手册补充](review-modes.md)，由子 Agent 读，主 Agent 不读；产品工作区另有 [产品工作区评审补充](workspace-review.md)，同样由子 Agent 读。

先从任务路径带入四项：新建或存量、是否只读、是否打分、当前轮次；再叠加页面领域标准。领域标准只决定检查什么，不改变任务的权限、轮次和停止点。没有评分要求的只读评审沿用“给已有界面评审”的不打分方式。

## 评审轮次

需要独立视觉评审时，默认执行 **1 轮独立盲审**；只有首轮发现结构级硬伤并重做后，才追加 **1 次复核**，不跑多轮机械凑分循环：

1. **首轮盲审**：按派发协议交接，评审给出排好序的问题、提升建议、“保留”一行和分数。无阻断缺陷时，主 Agent 修完关键项并自查后即可交付，不再派复核。
2. **重做后的单次复核（按需）**：若首轮触发结构重做或存在严重阻断问题，改完后只重新取得受影响的画面和动效证据（录屏条件按 [工具](tools.md)），派子 Agent 对照上一轮问题清单复核一次即可收尾交付。

## 开放式 UX 走查

在 [轻量 UX 走查派发](ux-review.md) 的基础上，当页面包含复杂多步流程、或用户要求深入排查交互风险时，可按需触发一轮带自主风险探针的走查。默认触发条件、交接材料与主 Agent 功能验证照那份文件执行。

提示词用：

`请读取 references/review-modes.md，按照【任务走查】的【开放探索】执行。先完成轻量主路径，再自主选择一个相关风险点检查，记录实际观察到的体验障碍。页面地址、主视口和必要测试材料如下；窗口可不同，仅尺寸相关的问题需要在主视口复现。`

主 Agent 根据报告修复真实可复现的交互障碍后，由主 Agent 自己完成保存、刷新读回和失败恢复验证，不强制再派第二轮 UX 复核子 Agent。

## 复核、多方向、任务走查与方案评审

| 你做了什么改动 | 子 Agent 的提示词 (Prompt) 模板 |
| --- | --- |
| 重做后按需复核上一轮问题 | `请读取 references/review-modes.md，按照【复核】标准，对照附上的上一轮问题与提升清单检查当前画面证据和必要的对应操作，然后重新打分。` |
| 几个方向都做成了完整页面，或用户要求评审几个首屏 | `请读取 references/review-modes.md，按照【多方向横向对比】标准，检查提供的多张方向截图是否属于同一骨架换皮。` |
| 涉及复杂业务流程或交互链路的更改（按需） | 按上面的“开放式 UX 走查”派发，不在提示词里另写具体任务。 |
| **评审改流程和加新功能的方案**：改流程或加新功能出了几个方案 | `请读取 references/review-modes.md，按照【改流程与加新功能方案评审】标准，比较提供的几个方案，指出假差异、补丁和每个方案最可能失败的场景。` |

模板里的路径按 [派发协议](visual-review.md) 换成绝对路径。

小游戏、抽奖、计时养成这类产品，派发全新界面评审时在提示词末尾加一句：`另按 references/play-craft.md 的“交付和评审时多查几项”核对。`

## 产品工作区评审

工作区的新建、存量优化、只读、组件和复核都带上领域标准；小改动仍由主 Agent 自查，不因补标准而派评审。

在 [视觉评审派发协议](visual-review.md) 的对应模板后补充：`本次领域是产品工作区。先读 references/workspace-review.md，以它作为内容标准；任务类型、是否只读、是否打分与本轮范围如下：……。不要套用海报页的主角、字体性格、实物配色与装饰扣项。` 单组件也用这套标准与任务模式，范围只限该组件，不使用组件文件的表现性评审模板。

用户提供了参考图时，交接参考与按 [工作区骨架](direction-workspace.md) 的“并排对照，交给别人判断”得到的可比画面；没有实际参考时不编造对照。存量任务同时交接锁定规范与获准变更项。第二轮起只复核上一轮问题，评分沿用工作区锚点；不每轮重新读一套海报规则。

工作区评分表示视觉完成度，功能验证单独报告。上方“评审轮次”的收尾交付均要求无已知阻断缺陷；有用户质量基线时，还须有领域评审对可比维度达到基线的结论，不能以操作可用或分数上涨代替。轮次与上限不增加，达到上限仍有视觉差距或阻断缺陷就如实交付剩余问题。

明确比较工作区方向或版式时，比较它们是否在本次获准的维度上存在实质差别。共用品牌、组件、对象或操作习惯本身不算同构换皮；只改装饰却没有回答比较目标时才指出。此条替代 [评审手册补充](review-modes.md) 的通用横向查重标准。
