# 方向贯穿整页

方向选定、首屏做出来以后，用这份文件把方向延续到首屏以下的每个区块。认品类、定骨架和差异检验见 [设计方向](design-direction.md)。

方向不只属于首屏。首屏以下的每个区块，都要用这个方向自己的语言重新设计，形式从选定的方向和概念推出。模型最容易在首屏用尽力气，到了第二屏就回到通用的卡片、分栏和居中结尾。

- **区块的顺序和取舍也属于方向。** 不照“首屏、对象介绍、三步流程、一句结尾”排下来再逐块换样子。由方向决定先讲什么、合并什么、删什么：可以把流程并进对象介绍，也可以整页只讲一个对象。产品界面也一样。
- **相邻两屏不共用同一种构图，分界与疏密跟着方向走。** 把每一屏的构图概括成一个词。同一个词不连续出现两次，不连续多屏沿用等宽左右对半切分，也不把每一屏都封进带底色的卡片盒子里。区块之间怎样分界由方向决定：可以是细线，也可以直接排在底色画布上，靠留白、字号反差或底色切换分段；不给每个区块上下都顺手加一条通栏细横线。首屏以下可以按内容选用这几类组织方式，具体长相从方向里推：
  1. **图文错落**：多段说明与配图直接排在开放画布上，两列在纵向错开，图像与段落交错，不排成齐头并进的方格卡片。
  2. **无框列表**：规格、功能条目或参数直接落在画布上，靠行距拉开；只有当前选中或悬停的那一行有变化，并联动旁边的画面。
  3. **固定主体配叙事流**：一侧钉住随滚动或点击变化的主体，另一侧依次滚过步骤、数据或证据。
  4. **首尾呼应的行动区与页脚**：结尾的行动区和页脚沿用首屏那套语言，行动区可以做成这个方向自己的一处专属载体，不到了底部退回默认表单。
- **拿掉多余边框后靠四样东西撑起分量。** 不套多余卡片框、不画满屏分割线后，靠这四样东西让画面既有呼吸感又不空洞：
  1. **拉大字号对比，正文给足尺度**：展示大字和正文拉开数倍的差距，阅读型页面的正文不靠局促小字凑精致感。
  2. **把真实业务明细写全**：题面给出的功能、规格、价格区间、周期或限制条件，每一项都把具体名字、数字和适用场景写清楚，不拿一句笼统口号代替完整信息。
  3. **同一套图像、实样或图形**：整页穿插足够的界面实样、同套画面或有层次的图形，不留两屏以上空洞的底色。
  4. **整页共享 2–3 条垂直左对齐锚线**：标题、正文列、价格表和页脚沿用固定的 2–3 个左起点，让高低错落的构图依然保持严谨的网格秩序。
- **首尾和导航也跟着方向走。** 导航栏、结尾行动区和页脚的字号、边框、留白和按钮，要和首屏是同一套语言，别到了头尾就退回默认样式。
- **逐区块对照首屏。** 整页截图后逐块看：哪一块换到别的方向里也成立，就回到方向重做这一块。

几个方向都做成完整页面时（用户要求，或版式变体做到整页），再加三条：

- **候选共享内容，不共享实现。** 同一份示例数据可以共用；区块结构、样式和代码不共用，不把某个区块写成共用模块再给各方向换颜色。产品本身的组件不在此列：设计组件库官网或已有产品时，各方向照常使用同一套真实组件，差异体现在怎样编排和呈现上。
- **同一条修改意见，翻译成每个方向自己的做法。** 不用同一种实现套到所有方向上。
- **逐区块横向比较。** 各方向的整页截图并排，按区块一一对照；任何一个区块在两个方向里看起来是同一个东西，就回到那个方向重做。
