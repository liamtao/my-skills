# 产品工作区评审补充

评审者读，主 Agent 由 [评审循环与扩展派发](review-loop.md) 派发。适用于 SaaS 产品、后台、控制台、队列、编辑器和数据工具；设计规则的来源是 [工作区骨架](direction-workspace.md)。这里只检查结果，不重新设计产品。

## 先确定评审模式

交接材料应有用户任务、页面领域、改动范围、目标视口和现有规范。先确认是否打分、是否只读、是否复核；材料缺失就说明限制，不自行升级任务。

- **新建与重塑**：按本文件评审，使用下方评分锚点，轮次由主 Agent 决定。
- **存量整理、升级、加功能或改流程**：以锁定规范和授权范围为准，指出偏离与可观察缺陷，不打分，不要求更换整体风格。
- **只读评审**：只交问题与建议，不改文件、不进入修正循环；默认不打分，用户要求评分时才使用锚点。
- **复核**：先核对上一轮问题，再报告这批改动带来的直接问题，不重开完整检查清单。
- **截图还原**：参考图决定可见结果，不以本文件的默认风格改造它；交互只核对已约定的范围。

[评审手册](reviewer-manual.md) 只沿用证据边界、可读性检查与问题清单格式。工作区不套用海报主角、字体个性、实物取色、装饰数量或开放画布的扣分项；圆角面板、纯文字 Tab、中性色按钮和系统字体都可以成立。使用组件库本身不扣分，但仍核对字号、间距、颜色、密度是否落实到本产品的设计系统，不能把默认皮肤当成完成度依据。

## 结果检查

| 维度 | 看什么 | 何时才提出修改 |
| --- | --- | --- |
| 对象与导航 | 当前组织/项目/对象、所在视图与动作范围能否辨认 | 身份混淆、跨范围操作不清、重复标题挤出工作内容 |
| 身份素材是否完整 | 人物、组织、平台与内容的素材是否匹配、清晰，并在列表和详情中稳定对应 | 有可用身份素材却仍用字块、重复占位头像或通用图标；素材与身份错配。真实缺失与匿名状态的合理兜底不算缺陷 |
| 信息与密度 | 第一屏能否同时看到主数据、判断依据与下一步，整体空间与局部间距是否都成立 | 品牌区及组织切换占位过大、标题与工具挤出数据、固定高度造成空洞，或为了多放数据把标签、数值和说明挤紧；分别指出外层和局部的问题 |
| 画面的主要对比在哪里 | 首要关注点是否清楚，主色、辅助对比色及明暗、字号、面积是否各有职责 | 全页同色染灰、视觉重量平均或主次层次不清；不要求已锁定的单色系统换色 |
| 不同模块通过什么形成共同语言 | 字体层级、间距、素材裁切、图形笔触、图标与组件是否呼应 | 各模块各用一套，或只有相同圆角与边框、缺少约定的共同细节；需指出具体位置 |
| 信息组织 | 内容是否共同支持一个判断，异常能否追到对象、依据与后续动作 | 只有孤立数字与重复卡片，缺少完成当前任务的依据；不能仅因模块少就要求加卡片 |
| 核心信息怎样被视觉化 | 趋势、组成、排序或关系能否被直接比较，时间、单位、基准、空值与准确值是否清楚 | 只堆文字数字使主要比较困难，或图形没有依据、误导比例、只靠颜色；单值无需强配图表 |
| 控件内容与边界 | 实际阅读尺寸下，最长值、前后缀、箭头、焦点与展开状态能否各处其位 | 文字压箭头、箭头贴边或重复、内容被裁、焦点遮挡、浮层被截；不把正常焦点外扩误报为溢出，不把无页面滚动条当作已通过 |
| 操作与状态 | 主次动作、当前/焦点/选择、加载/空/失败/权限能否区分 | 无法判断作用对象、伪成功、恢复入口缺失或输入丢失 |
| 连续性与动效 | 切换、关闭详情、刷新和快速重复操作后是否仍能定位 | 位置丢失、焦点错位、动效阻塞或重复播放；仅有截图时不推断手感 |
| 跨页复用 | 新页面或状态是否沿用共同变量、组件与操作习惯 | 无理由另起一套，或未经授权改变现有设计系统 |

纯文字、留白、没有微图表或没有图标都不是缺陷本身；它们不能成为省略已有身份素材、主要比较关系或约定视觉对比的理由。提出新增元素时，说明它解决哪项已观察到的问题；不为满足配额增加图标、徽章、指标或动效。

有用户参考或已取得的同任务参考图时，在可比视口与状态下指出具体差距；没有参考图不编造品牌对照，也不为完整性要求重取全部证据。功能与视觉分别陈述，截图不足以证明操作已通过。功能通过不能抵消明显的视觉差距。

用户把参考设为质量基线时，分别比较身份素材、信息表达、主要对比、共同语言以及整体与局部的空间分配，给出“达到、仍有差距或不可比”及可见依据。同一业务任务才能直接比较首屏对象数量；跨业务参考比较完成度，不要求工单队列复制概览图表。不可比的维度说明原因，不能借此把整张参考判成无关；有明显差距时不能只凭无功能缺陷给高分。只有整页缩略图时，控件内部边界和局部密度标为未验证，需要时补受影响局部的原尺寸画面；不重取无关页面。

## 输出与评分

按影响给出最多五项问题与必要的细节改进，每项包含位置、观察、影响、修到什么程度算完成；最后写一行应保留的做法。不把个人口味写成阻断问题。

只有打分模式才追加分数及具体差距：

| 分数 | 依据 |
| --- | --- |
| 9–10 | 已观察的身份素材、信息表达、视觉对比与共同语言均落实，整体空间和局部细节完成度高，主要工作内容充分可见；有质量基线时，可比维度达到基线，只有细微差距。仅无明显缺陷不够，未解决的占位素材、控件挤压或明显拥挤不能算完成 |
| 8 | 结构与视觉整体成立，但仍有具体的层级、空间、信息组织或细节差距；明确最影响完成度的剩余项 |
| 7 及以下 | 视觉仍停留在粗稿：大面积色彩混浊、空间分配明显失衡、主体缺少判断依据或细节系统混乱等；即使主要操作可用也可落在此档，按程度降低 |

分数表示视觉完成度；已观察到的任务阻断、数据丢失、伪成功、不可读或误导数据另列为阻断缺陷，不被视觉分数抵消。证据不足的项标为未验证，不能当成通过；评分不代表真实用户成功率，也不替代用户的审美判断。
