# 工作区数据、视图与图表

上级入口：[工作区骨架](direction-workspace.md)。这里规定复杂多维报表与队列的数据怎样支持比较和判断，不另定视觉主题，无需额外预读其他交互文件。

## 表格与视图状态

- **先定列的职责。** 每列用于识别、比较、状态或动作；把决定是否处理该对象所需的信息留在列表，详细分析进入详情。长名称、空值和异常值都能区分对象，不靠所有行一样长的样例通过验收。
- **按数据对齐。** 名称留够宽度，文本与数字各按扫视方向对齐，可比较数值启用 `tabular-nums`，单位与精度统一。技术 ID 需要识别、核对或复制时可以成为主字段；截断保留可辨别部分，并提供完整值。
- **可视化要有判断用途。** 需要连续比较比例、排名或接近阈值时，用可直接扫视的长度、位置或进度表达，同时保留准确值；只有单个数量、时长或没有可靠分母时用文字即可。身份素材按 [工作区骨架](direction-workspace.md) 的身份素材规则完成，无需把每个字段和状态都图形化。
- **排序与筛选可解释。** 当前排序方向、筛选条件、结果数量与数据一致；无结果保留条件并允许清除。选择超出当前页或筛选范围时明确数量与范围，不静默执行隐藏对象上的批量动作。
- **视图保留上下文。** 切换同级视图或关闭详情后，保留仍适用的查询、排序、当前位置；刷新后的保留方式按产品能力实现。换了组织、项目或数据范围时不沿用失效选择。

## 指标与图表

| 要判断什么 | 数据与呈现 |
| --- | --- |
| 当前数量或额度 | 准确值、单位和范围 |
| 一段时间里的变化 | 用位置或长度呈现真实时间序列，标出必要的对比或异常；时间范围与采样粒度明确，无序列不造趋势 |
| 类别差异或组成 | 差异用可比较的长度与排序，组成用有可靠总量的比例；类别颜色稳定，不只平铺孤立数字 |
| 对象之间的关系、位置或内容差别 | 使用与判断匹配的关系视图、位置视图或内容预览，同时保留对象名称和入口；没有相关数据不添装饰图形 |
| 异常与待处理项 | 显示原因、影响范围与对象入口，不能只给红色数字 |

图表轴、单位、时间范围、对比基准和数据是否完整要可理解；数据缺失与真实为零分开。真实页面沿用真实口径，原型采用自洽且包含正常、异常、空值的样例，不伪造实测结果。

存量项目沿用已有图表方案；新建工程优先用 shadcn/ui Charts（Recharts），无需构建的独立页面优先用 ApexCharts（或 Chart.js / 原生 SVG），网格和边框退后，比较对象或异常按语义突出；系列色与重点色沿用工作区的色彩分工，线条、端点、标记和标签形成共同语言，不随机给每类数据上色。重要数值能通过悬停、键盘聚焦或旁边的文字读到，不能只有颜色。点击图表会过滤列表时，条件、清除入口与列表计数同步；没有这项任务时不强加联动。

指标组拉开标签、数值与比较说明的间距；按最长数值和说明核对列宽，横向放不下时调列数、宽度或换行，不靠压缩行距、缩小字号或截断关键数值硬塞。

## 让信息形成工作闭环

- **概览**：围绕一个主要判断，组织相关总量与比较、变化或组成、需要关注的对象及明细入口。按实际数据选择需要的部分，不要求凑齐所有类型。异常同时给出原因或影响、具体对象与后续动作，让用户能从概览追到依据。
- **对象管理**：列表给筛选与比较依据，详情给当前状态、相关记录和可执行操作；补充信息围绕选中对象变化，避免一组无关全局指标把工作列表挤到首屏以下。
- **连续处理**：队列说明优先级或待处理原因，详情提供内容、关联对象、负责人和处理记录中确有用途的部分；用户处理后能看到结果并继续下一项。

同一范围内的总数、拆分、明细与状态互相对应。原型也应让异常有具体记录、筛选后有匹配对象、操作后有一致变化；模拟数据的变化要支持判断，不能只换名称填满重复行。

## 验收

在目标视口用一条正常记录、一条长名称或空值记录、一条异常记录核对识别与对齐。实际执行一次筛选、排序和进入/关闭详情，确认数据、计数与位置一致；页面没有的功能不为验收而添加。
