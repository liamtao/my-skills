## 概念交给子 Agent 出

派全新的子 Agent 独立出概念，由主 Agent 挑选。为单个方向构思时，从下面五个角度中挑 2–3 个互补的角度，各派一个；用户明确要求多方向探索时才用齐五个。可以和拆标杆并行，但不提前越过确认点。这一步替代 [设计方向](design-direction.md) 的通用概念子 Agent，选中以后的把关仍按那份文件的“独立概念生成与把关”第 4 步。每个只给产品、受众、和同类的不同，以及一个出发角度；不给标杆截图，不给主 Agent 已有的想法，不给其他子 Agent 的结果。提示词：

```text
你在给一个产品的落地页想首屏概念。只根据下面的信息想，不查同类产品，不读文件。

产品：<它是什么，替谁做什么，一两句>
受众：<是谁，来这页之前的处境>
和同类的不同：<一到三条>
出发角度：<下面五条之一的原文>

交回 3 个彼此不同的概念，每个写四行：
1. 概念：一句话，把产品的主张说成一个画面。
2. 标题：页面上的原文，不超过两行。
3. 主视觉：首屏最大的那样东西是什么、长什么样，写到能照着画出来。
4. 只属于这个产品的理由：换到同类另一家为什么不成立。

不写版式、配色、字体和页面的其余部分。
```

可选的五个出发角度，每个派出的子 Agent 只取一条：

- **受众的处境**：从受众来这页之前卡在哪、担心什么、想变成什么样出发，不从产品功能出发。
- **借一样东西**：找一个受众一眼认得、和产品主张道理相通的事物，用它来说。首屏不出现产品界面。
- **说反话**：这个品类人人都在说的那句话是什么，从它的反面或它没说的那一半出发。
- **一句话加一张图**：首屏只有一句话和一张图，图不是产品界面。
- **另一个领域**：这个主张放到一个和软件无关的领域里会怎样被表现，借那个领域的表现形式。

宿主不能派子 Agent 时，主 Agent 按所选角度各写 3 个概念，再取标杆画面；后续看图或补画面也按同样问题自查，交付注明未隔离。

## 选择对外方向

1. **先删。** 彼此重复的；标题换个产品名也成立的；和拆过的标杆首屏是同一个意思的。
2. **再验。** 剩下的逐个过三条检验。
3. **按对外数量选择。** 默认选检验里最站得住的一个；明确探索多个时才选多个。需要三个时选彼此最远的三个：概念各不相同，不是同一句话的三种排法；至少一个的主视觉是一张图，画的不是产品界面；以产品实样为主视觉的至多一个。
4. **各写各的。** 标题、副标题和主视觉每个方向各写各的；产品事实和示例数据（名称、功能、价格）共用。副标题用一句平实的话说清产品是什么。
5. **再选骨架。** 每个概念从 [说服型骨架](direction-persuasion.md) 的表里选骨架；同一轮有多个方向时骨架互不相同。
6. **写进方向卡。** 方向卡加一栏“概念”：这句概念、来自哪个角度、三条检验的结果。对比页 manifest 的 `concept` 仍填北极星，概念这一句写进 `traits`。

文字提案写明标题原文和主视觉。获准制作首屏后，图像制作按“整页的图做成一套”，出图前读 [素材](media.md) 的“写提示词”；概念选择中的截图与子 Agent 不替代交付前的取证和评审。

标杆只提供基线：这页要回答的问题和主动作的位置。标杆首屏的构图不算基线，算套路。

## 三秒检验

做了几个首屏、又没有用户来选时用这一节。只有一张首屏时不用另派，独立评审自己会做三秒测试。

1. 把首屏截图和标杆的首屏截图（有的话）一起交给一个全新的子 Agent，不给方向名和说明，问：哪一张遮住品牌名会被当成标杆里的某一家；每一张看三秒以后还记得什么；有多个时，哪一张最让人想往下看，为什么。
2. 先去掉会被当成标杆的；有多个时，再从剩下的里选“还记得的东西”最具体的那一个。
3. 只要副标题和第二屏能把产品说清楚，首屏不必把所有功能解释完；优先选看三秒还能记住具体画面的那一个。
4. 写明选了哪个、子 Agent 怎么说；有多个时，再写其他方向为什么落选。

请用户挑选时，推荐理由先写这两条：会不会被当成标杆，让人记住的是什么。还没有首屏、只有文字时，主 Agent 自己按这两条判断。

## 首屏以下派子 Agent 补构思

只对画面表里落回通用模板、或延续不了概念的区块派发，其余区块主 Agent 自己写。每个新子 Agent 只给定稿首屏的截图、概念、标题、尚未解决的问题和一个出发角度；不给标杆截图，不给主 Agent 打算怎么排，也不指定用什么通用区块回答。提示词：

```text
一个落地页的首屏已经定了，附图是它的截图。
概念：<那一句概念>
标题：<页面上的原文>
这页还要回答这些问题：<问题清单>
出发角度：<下面三条之一的原文>

为这些问题设计首屏以下的几屏，可以合并或调换顺序，让每一屏是首屏那个想法的下一句。每屏写三行：
1. 小标题：页面上的原文。
2. 画面：这一屏最大的那样东西是什么、长什么样、和首屏的图是什么关系，写到能照着画出来。
3. 产品事实落在哪：数字、功能、价格这些必须出现的内容，放在这个画面的什么位置。

不要退回“三列小图标配标题”的通用模板，也不要放和概念无关的通用示例截图。哪一屏确实只需要文字、对比表或几张具体的特性卡，直接说。
```

可选的三个出发角度，一个子 Agent 一条：

- **同一样东西往下走**：首屏的那样东西在每一屏换一个时刻、角度或局部。
- **它的同伴**：每一屏一样新的东西，和首屏的图同属一套、同一种画法。
- **一个连续的变化**：从首屏到结尾是同一件事的经过，每一屏是其中一步。

派回来的结果并进画面表，再写整页代码。

## 整页的图做成一套

以图为主视觉时，先按交付材料选一条路线，两条不叠加。

### 已有整页 UI 设计稿

沿用设计稿的主视觉，不跑主图候选批次。文字、结构与图形先用代码表达，图像复用已有资产或稿中清晰的独立素材；仅代码无法表达且无可用原图的首屏视觉补 1–2 张独立高分辨率素材，画面与画法服从设计稿。提取与接入见 [生图设计与还原校准](image-ideation.md#检查测量与响应式实现)。

### 单独制作配图

无整页设计稿、需要独立主视觉及配图时（若用户已选择跳过生图或无生图授权，改按 [素材](media.md) 选用现有资产、检索公开素材或代码图形，不执行下列生图步骤）：

1. **主图定稿。** 单方向主图候选合计限 2–3 张；明确多方向探索时，每个以图为主视觉的方向可出 2–4 张，服从用户数量与授权预算。已有候选够用就选定。沿用概念的主体和画法，拉开姿态、构图与细节。逐张放进真实首屏，拼图比较：与标题是否表达同一件事、文字是否压得住、缩小一半是否仍能辨认。记录选择与落选理由，选中的再高画质重出或精修，透明底在此处理。
2. **其余的图从主图改出来。** 画面表里每一张新图，都拿定稿的主图当参考图来生成，提示词写明沿用它的材质、光向、视角和色板，换的是主体、时刻或角度。宿主不能传参考图时，先把主图的画法写成一段风格说明，原样放进每一条提示词。每张先出 1–3 张候选，放进它所在的那一屏挑定。
3. **需要材质或底纹时，再出一两张这一套的。** 用在卡片底、表头和分隔上，页面不留和这套图无关的色块；页面本身是干净纯色底时不硬加。已有合适的同套现成素材可以直接用。
4. **拼素材并排图，交给子 Agent 看。** 主图、画面表里的新图和用到的材质，拼成一张图存进任务目录。派一个全新的子 Agent，只给这张图，问三件事：哪一张不像同一套；哪一张像通用素材库里的图；哪一张缩小以后认不出主体。被点到的重做。
5. **放进页面以后接起来。** 逐张对照 [素材](media.md) 的“让图和页面接成一体”：主视觉和跨区块的大图不要关在小卡片里，按画面做背景融合、透明底跨界、文字压图，或者需要指明图里位置时用代码画线接出去。
