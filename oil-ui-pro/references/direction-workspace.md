## 流程与规则优先级

任务类型与交付范围由主入口决定，本文件不重新开启方向选择、确认或实现。新建、续作、存量优化、加功能和评审都使用同一套工作区知识，应用范围如下：

| 已选任务 | 本文件怎样使用 |
| --- | --- |
| 新建产品，或获准重塑工作区 | 先定对象、导航与设计变量，再做代表性页面；方向确认沿用主入口的停止点，已授权直接做时继续 |
| 继续已定方向 | 沿用已有设计变量与结构，只补本次新增对象、组件或状态，不重新选风格 |
| 单个工作区组件 | 按下方“单个工作区组件”限定构思、状态与评审，只补该组件的职责，不扩成整页重设计 |
| 存量整理、升级、改流程或加新功能 | 先按 [存量项目](existing-project.md) 锁定范围，再用本文件检查或补齐缺项；没有 DESIGN.md 不等于可以重做，已有变量、组件和同类页面也是依据 |
| 明确比较方向或版式 | 候选共用产品事实、对象和锁定规范；比较任务结构、信息层级或获准改变的视觉语言，不为差异而改操作习惯 |
| 截图还原 | 参考图决定可见布局与样式；只补参考未给出的操作和状态，不以默认设计系统重设计参考 |
| 只读评审 | 用于识别领域和约束，不改文件；按主入口派发与停止 |

以下覆盖在工作区的构思、实现、自查和评审阶段都生效：

- 用本文件的骨架与变量规则替代 [设计方向](design-direction.md) 的概念候选、五刻度、跨领域类比、方向卡、灰度把关和差异检验；不读取该文件来补这些前置步骤。复杂结构可画线框解决问题，不把线框当统一必交物。
- **常规单页工作台或控制台，直接按本文件与 [工具](tools.md) 即可完成设计、实现与自查，不要再去预读 `visual-language.md`、`visual-polish.md`、`layout-and-viewport.md`、`motion.md` 等通用文件。** 视觉以本文件的变量和组件规则为准，不把通用文件里的字体性格、实物取色、单色预算、单一海报主角当作必做步骤。
- 主入口的产品事实、真实截图、功能验证与能力边界仍适用。常规过渡与反馈以本文件的“阴影与动效”及“数据、列表与高频交互”为准，复杂高频交互见 [工作区交互](workspace-interaction.md)；评审按 [评审循环与扩展派发](review-loop.md) 的“产品工作区评审”派发，不由领域规则改变是否打分、轮次和停止点。
- 首屏布局、顶栏、单文件、数据自洽和截图范围以本文件为准，[设计方向](design-direction.md) 和 [工具](tools.md) 里的同类说法不另叠加：三行布局只用于多模块工作台；顶栏合并只在单页工作台尽量做；单文件只在没有工程约束时；数据只要求静态原型直观自洽；工作台一律不跑 `--full`，不只限 [工具](tools.md) 点名的带 `sticky` 或 `100vh` 的页面。

## 页面骨架与导航

| 用户主要在做什么 | 优先考虑 | 第一屏要看见什么 |
| --- | --- | --- |
| 比较同类对象、筛选和批量处理 | 工具栏 + 表格或列表 | 对象身份、判断字段、当前筛选与可执行动作 |
| 连续查看并处理单个对象 | 队列 + 详情 | 当前位置、判断依据、操作结果与下一条 |
| 配置一组参数 | 分组表单 | 字段关系、作用范围、保存方式与校验 |
| 阅读或编辑内容、代码与数据 | 内容或编辑画布 + 按需出现的辅助面板 | 工作内容与直接作用于它的工具 |
| 了解变化并决定下一步 | 有依据的概览 + 可进入的对象集合 | 时间范围、变化或异常，以及查看明细的入口 |

- **按对象与范围分导航。** 组织/项目切换、跨对象的全局导航、同一对象的 Tab 分清层级。当前范围与当前位置可辨；Tab 只切同一范围的同级视图，不承担无关页面跳转。
- **操作靠近作用对象。** 页面操作靠近标题或筛选工具栏，行操作留在行内或“更多”，批量操作在明确选中范围后出现。多个区域可以各有主动作，强调程度按当前任务排序。
- **宽度与密度跟随内容。** 表单和阅读内容限制行长；日志、代码、宽表格使用所需横向空间。同组间距小于组间间距，先保住辨认与点击空间，不设统一行数配额。减少外层空洞时先收紧无职责占位，不把标签、数值与说明挤成一团；局部拥挤先调分组、列宽或换行，不把全页间距一起放大。
- **把首屏空间交给判断（1440×900 视口内同时露出全貌）。** 目标视口内应同时看见主数据、判断依据和下一步动作。多模块工作台（含核心指标、态势主图/图表、动态时间轴、主数据表、排行榜等）应采用紧凑的 3 行式 Bento 网格（例如：第 1 行 4 张紧凑指标卡，可将评分环直接内嵌在对应指标卡内，避免单独做一张 400px 高的大圆环卡与指标卡重复；第 2 行态势主图 + 时间轴；第 3 行主数据表 + 热门排行），确保在 `1440×900` 桌面视口内**所有核心模块与主表前 4–6 行都能完整露出**，不要把页面撑到 1400px 以上导致主表和排行在首屏被截断。标题、描述、Tab、筛选和指标叠成多层时，先合并同作用域工具、压缩重复上下文和独立指标容器，不靠缩小字号或点击区域补救。
- **按关系分配空间。** 同一判断的总量、对比与趋势可合为连续区域，辅助判断收窄，无主次差异时才等分。图表绘图区随容器铺开，避免外框很大而图形挤在中央；不留无内容支撑的固定高度空洞。
- **渐进展开。** 列表保留比较与选择依据，详细证据、低频设置和复杂编辑进入详情。要对照列表时用伴随面板；需要独立地址、长内容或多步工作时用完整页面；阻断决定才用模态框，细则见 [空间、滚动与浮层](layout-surfaces.md)。
- **只画有职责的边界。** 同一边界不重复描画；不强制三层卡片，也不因存在嵌套就拆掉独立分组。

## 设计变量与组件

存量项目优先沿用已经安装并实际使用的组件库、图标库和样式体系，先按 [存量项目](existing-project.md) 确定现行标准。新建项目按技术栈和主要交互选择组件基础：原生控件、轻量基础组件或完整组件库均可，不强制引入完整库；复杂选择、浮层和键盘交互优先采用能覆盖需求的成熟实现，图表可按技术栈选用 Recharts、ApexCharts、Chart.js 或原生 SVG/Canvas。只为本次必要的组件引入依赖。

组件基础负责结构、语义和交互，视觉仍由设计系统决定。新系统或获准升级的部分，先把下表角色落实到项目已有 token 机制或 CSS 变量，再调整组件的字号、间距、颜色、密度和状态；不要逐页独立写取值，也不把组件库默认皮肤当成设计完成。

| 角色 | 决定与用途 |
| --- | --- |
| 表面 | 画布、内容区域、浮层；可按产品气质选用温润浅色画布配深色侧栏（如深墨绿/深松石侧栏 + 暖灰白纸感画布 + 鲜明信号色点缀）、清爽浅色或深色指挥台；允许用克制的柔光渐变或微染色高亮主指标卡（如核心达标卡用浅色渐变底）拉开视觉主次，不强制每层不同底色，也不退回单调的冷灰白+默认亮蓝 |
| 文字 | 主文字、辅助文字、禁用文字；靠字号、字重、对齐共同分层，辅助信息仍过可读性门槛 |
| 边界与焦点 | 默认分隔、控件边界、键盘焦点；焦点与当前页、选中状态分开 |
| 色彩 | 结构色、主强调色与辅助对比色各有职责，确定出现位置、视觉重量与复用方式；状态色与数据系列有独立语义，同义跨页一致 |
| 字体与数字 | 正文、标题、数据各指定角色与少量层级，可共用同一字族；可比较数字使用等宽数字特性，技术标识按任务需要使用等宽字体 |
| 空间与形状 | 一套间距、控件尺寸、行高与圆角档位；同行输入、下拉与按钮等高，密度变体有任务含义，嵌套圆角与内边距协调 |
| 阴影与动效 | 阴影与边框配合表面层级表达分组或浮起；持续时间和缓动共用，动态效果以连续和安静为先 |

先在代表页固定导航、工具栏、Tab、列表行、表单与反馈的必要组件或变体；页面没有的组件不预建。至少检查一个正常状态和本任务最容易出错的状态，再把组件铺到下一页。

再按原尺寸看局部、缩小看整体，核对以下关系：

- **色彩有主次与呼应。** 主强调色与辅助对比色在关键操作、数据和图形中按职责呼应，不只给按钮换色。用实色、底色对比与线条拉开强弱。
- **数字有层级。** 主数值、比较说明与标签拉开字重和大小；关联指标靠对齐与分隔成组。
- **间距形成节奏。** 按页面边距、模块间距、模块内边距和同组信息四级选值，做到同组紧、跨组松。

- **导航与 Tab**：文字能辨认时即可；图标辅助识别，计数帮助选择时才加。当前项有稳定可见的标记；键盘焦点另有表达。
- **状态**：按重要性选择文字、图标、圆点或徽章；普通状态保持安静，需要处置的异常更醒目。颜色不能独自传递含义，也不要求所有状态套胶囊。
- **按钮与输入**：名称说明动作和对象；主次强调一致，输入标签与报错位置稳定。必要但暂不可用的动作说明原因，恢复条件满足后可用；不为画面完整虚构可执行状态。
- **身份素材**：人物、平台、组织与产品使用清晰的头像、标志或缩略标识，并保留名称。身份图仅用于识别对象，不套用海报主视觉的占屏、破界或单色化手法。
- **通用图标**：需要时默认选一套成熟图标库，沿用项目已装库，统一视觉尺寸、线宽、端点与文字对齐；不混用字符、Emoji 或不同画法。品牌 Logo 保留真实形状与品牌色，不强行改成通用图标画法。

## 单个工作区组件

[组件](component.md) 的深度打磨用于单个控件、数据组件或操作面板时，以本节替代其中的表现性流程：

- 写清组件回答的问题、信息、操作、实际需要的状态和承载尺寸；沿用系统的文字、数字、颜色和控件，不为普通选择器补暂停、计划中等无关状态。
- 文字或数字能清楚回答问题时即可，不要求实物主视觉、三层画面、母题取色、第二款标签字体或遮字辨状态。图形确有判断价值时按工作区数据规则使用；状态不只靠颜色表达。
- 已有组件与模式直接深化；只有获准改变且存在结构问题时才做内部候选。交互沿用工作区专项，不默认数字滚动、阻尼、吸附或独创控件。
- 取实际使用尺寸及必要的局部放大图，覆盖本次相关状态与主要操作。按 [评审循环与扩展派发](review-loop.md) 的“产品工作区评审”交接，任务范围仍只限组件；替代组件模板的遮字图、品牌差异封顶、分享瞬间和固定打分要求。不另做取色背景的作品图，除非用户需要展示图。

## 页面标题与身份

页面标题说明当前对象或任务，不在品牌行、面包屑和标题中重复放大；**顶栏与标题合并**：单页工作台尽量将面包屑/标题、实时状态与全局搜索/时间筛选合为一排紧凑顶栏（高约 `56–64px`），不要叠双层高顶栏浪费纵向空间；上下文足够时可省去大标题或描述，让工作内容直接进入首屏，不为填空加口号或说明。

## 数据、列表与高频交互

常规工作台与后台直接按本节完成数据呈现与交互闭环，无需预先通读其他专项文件：

- **表格与对齐**：每列明确负责识别、比较、状态或操作；决定是否处理该对象所需的信息留在列表，详细证据进入详情。名称留够宽度，可比较数值启用 `tabular-nums` 且单位与精度统一；长名称、空值和异常值都能清楚区分。
- **指标、图表与数据自洽**：总量、趋势、分布和异常围绕当前判断组织；同一范围内的总数、拆分、筛选计数与明细互相对应。**静态原型或单页演示的汇总数字与明细保持直观自洽即可（如异常计数与列表异常行数一致），严禁在写代码前专门编写 Node/Python 脚本去验算多维财务公式。** 样例数据包含正常、异常和边界记录，异常项同时给出原因、影响范围与具体对象入口。
- **交互闭环与上下文保持**：打通 `定位对象 → 查看判断依据 → 执行动作 → 看到结果` 的真实可操作序列。切换筛选、排序或打开/关闭详情抽屉时保留当前查询、滚动位置与焦点；操作反馈短促安静，局部更新，不让整页重新入场。

## 制作、自查与专项读取

常规单页工作台或控制台直接按本文件实现即可，**不要在动手写代码前把下方专项文件逐一通读**；仅在遇到下表列出的复杂专门场景时按需查阅：

| 需要深入的复杂场景（常规工作台无需预读） | 按需查阅 |
| --- | --- |
| 复杂多维报表、跨表联动口径或密集队列闭环 | [工作区数据](workspace-data.md) |
| 复杂键盘导航、拖拽编排、命令面板（`⌘K`）或批量部分失败恢复 | [工作区交互](workspace-interaction.md) |
| 复杂多栏嵌套、多层浮层遮挡或特殊独立滚动容器 | [空间、滚动与浮层](layout-surfaces.md) 与 [布局与视口](layout-and-viewport.md) 的相关节 |
| 人物、平台、组织或内容需要检索下载真实身份图片 | [素材](media.md) 的“复用、生成，还是交给代码”与“文件与说明”，按本文件的身份素材规则选来源 |
| 先生成工作区 UI 设计稿、存量 `--ref` 局部延展或测量校准 | [生图设计与还原校准](image-ideation.md) |
| 交付前跨页视觉精修与细节排障 | [视觉语言](visual-language.md) 的“可读性是交付门槛”与 [视觉自查与精修](visual-polish.md) 的“细节”，应用本文件的覆盖 |

- **单文件内聚优先**：没有工程约束的独立单页应用优先将 HTML、`<style>` 与 `<script>` 紧凑写在一个 `index.html` 中（除非任务明确要求多文件），避免拆成 3 个文件导致跨文件 CSS 选择器失配和多次写入耗时。
- **截图自查一步到位**：用 `shoot.mjs` 一次截取 `desktop,mobile` 标准视口（`1440×900` 与 `390×844`），必要时用 `--steps` 验证 1–2 个交互状态即可收尾；**严禁对工作台跑 `--full`（`fullPage: true`）整页拼接截图，严禁为了截图专门写 `?state=` URL 参数路由，也严禁对每个局部卡片逐一跑 `--selector` 截图**。
- **代表页与局部核对**：先完成代表性页面和关键状态，检查对象、范围和动作是否清楚，组件与状态语义是否一致，再扩展其他页面。自查同时看整体空间与原尺寸的选择器、指标组、身份列；页面没有横向滚动不等于控件内部没有裁切或挤压。调整密度、字号或共享样式后，复看受影响的这些局部及焦点、长内容状态，不用缩略图代替。自查用本文件的结构与组件规则，不增加评审轮次；独立评审者的标准只由评审派发入口交接。

## 并排对照，交给别人判断

用户提供或明确指定的可访问参考是质量基线，先区分借鉴与精准还原。借鉴时提取参考的身份素材、信息表达、主要对比与共同语言，同时观察首屏空间和局部完成度，记录本产品因任务不同必须改变的部分；不照搬参考的行业、品牌色或模块数量，也不凭品牌名臆测细节。

有可比较的参考图时，按相同视口、比例与状态，用 [工具](tools.md) 的 `--stitch` 并排交给评审者，差距写成具体位置与可观察结果。比例不同才用 `--match-width` 或 `--scale`，比较局部才用 `--crop`；未获得真实参考时，按本文件验收，不宣称已达到某个品牌的完成度。
