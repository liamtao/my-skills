# 产品工作区骨架

本文件负责 SaaS 产品、后台、控制台、队列、编辑器和数据工具的设计系统与页面模式。“工作区”指用户反复处理对象和状态的界面；SaaS 官网按说服型页面，浏览与挑选内容的页面按内容浏览处理。

常规的单页工作台读到本文件为止就能做完，[专项](#专项)表里的情况出现了才读对应文件。

## 和其他文件的关系

- 本文件替代 [设计方向](design-direction.md) 的概念候选、调性刻度、方向卡、灰度把关和差异检验，工作区任务不读那份文件来补这些步骤。视觉以本文件的变量和组件规则为准，通用文件里的字体性格、实物取色和单一海报主角不是必做项；复杂结构可以画线框解决问题，线框不是必交物。
- 任务范围、确认点和交付由 [主入口](../SKILL.md) 决定，本文件不重新开启方向选择：续作只补新增的对象、组件和状态；截图还原以参考图为准，只补参考没给出的操作和状态；比较方向或版式时，候选共用产品事实、对象和锁定规范，不为差异而改操作习惯。
- 存量项目先按 [存量项目](existing-project.md) 锁定范围，再用本文件检查或补缺。没有 `DESIGN.md` 不等于可以重做，已有的变量、组件和同类页面也是依据。

## 页面骨架与导航

| 用户主要在做什么 | 优先考虑 | 第一屏要看见什么 |
| --- | --- | --- |
| 比较同类对象、筛选和批量处理 | 工具栏 + 表格或列表 | 对象身份、判断字段、当前筛选与可执行动作 |
| 连续查看并处理单个对象 | 队列 + 详情 | 当前位置、判断依据、操作结果与下一条 |
| 配置一组参数 | 分组表单 | 字段关系、作用范围、保存方式与校验 |
| 阅读或编辑内容、代码与数据 | 内容或编辑画布 + 按需出现的辅助面板 | 工作内容与直接作用于它的工具 |
| 了解变化并决定下一步 | 有依据的概览 + 可进入的对象集合 | 时间范围、变化或异常，以及查看明细的入口 |

以手机为主要使用视口的 App 先读 [移动端工作区](workspace-mobile.md)，下面的桌面规则只取仍然适用的部分。

- **按对象与范围分导航。** 组织或项目切换、跨对象的全局导航、同一对象的 Tab 分清层级。当前范围与当前位置可辨；对象内 Tab 只切同一范围的同级视图，不承担无关页面跳转。
- **操作靠近作用对象。** 页面操作靠近标题或筛选工具栏，行操作留在行内或“更多”，批量操作在明确选中范围后出现。多个区域可以各有主动作，强调程度按当前任务排序。
- **页面标题与身份。** 标题说明当前对象或任务，不在品牌行、面包屑和标题里重复放大。单页桌面工作台把标题、状态和全局筛选并成一排紧凑顶栏，不叠两层；上下文足够时可以省去大标题和描述，不为填空加口号或说明。
- **桌面首屏交给判断。** 桌面主视口内同时看得见主数据、判断依据和下一步动作，多模块工作台的核心模块和主表前几行不被推出首屏。同一个数只出现一次，不为它另做一块重复的大图形。标题、描述、Tab、筛选和指标叠成多层时，先合并同一作用域的工具、去掉重复的上下文和单独占一块的指标容器，不靠缩小字号或点击区域补救。
- **宽度与密度跟随内容。** 表单和阅读内容限制行长；日志、代码、宽表格用足横向空间。同组间距小于组间间距，先保住辨认与点击空间。局部拥挤先调分组、列宽或换行，不把全页间距一起放大。
- **按关系分配空间。** 同一判断的总量、对比与趋势可以合成连续区域，辅助判断收窄，没有主次差异时才等分。图表绘图区随容器铺开，不留没有内容支撑的固定高度空洞。
- **渐进展开。** 列表保留比较与选择的依据，详细证据、低频设置和复杂编辑进详情。要对照列表时用伴随面板；需要独立地址、长内容或多步工作时用完整页面；阻断式的决定才用模态框，细则见 [空间、滚动与浮层](layout-surfaces.md)。
- **只画有职责的边界。** 分组按 [轻路径](light-path.md) 第 2 步的先后来：先用间距和对齐，表格行靠行距和斑马底色也能分开。同一边界不重复描画；不强制三层卡片，面板里的筛选、标签和选项不再各套一圈框。

## 设计变量与组件

存量项目沿用已经安装并实际在用的组件库、图标库和样式体系。新建项目按技术栈和主要交互选组件基础：原生控件、轻量基础组件或完整组件库都可以，只为本次必要的组件引入依赖；复杂选择、浮层、键盘交互和图表优先用成熟实现。

组件基础负责结构、语义和交互，视觉仍由设计系统决定。先把下表的角色落实到项目已有的 token 机制或 CSS 变量，再调组件的字号、间距、颜色、密度和状态；不逐页另写取值，也不把组件库的默认皮肤当成设计完成。

| 角色 | 决定与用途 |
| --- | --- |
| 表面 | 画布、内容区域、浮层。底色、侧栏和点缀色按这个产品的气质取，不停在冷灰白配默认亮蓝；可以用克制的染色拉开主次，不强制每层一个底色 |
| 文字 | 主文字、辅助文字、禁用文字；靠字号、字重和对齐共同分层，辅助信息仍过可读性门槛 |
| 边界与焦点 | 默认分隔、控件边界、键盘焦点；焦点和当前页、选中状态分开表达 |
| 色彩 | 结构色、主强调色与辅助对比色各有职责，定下出现位置、视觉重量和复用方式；状态色与数据系列有独立语义，同义跨页一致 |
| 字体与数字 | 正文、标题、数据各指定角色与少量层级，可以共用一个字族；可比较的数字用等宽数字特性 |
| 空间与形状 | 一套间距、控件尺寸、行高与圆角档位；同行的输入、下拉与按钮等高，嵌套的圆角与内边距协调 |
| 阴影与动效 | 阴影与边框配合表面层级表达分组或浮起；持续时间和缓动共用，以连续和安静为先 |

先在代表页固定导航、工具栏、Tab、列表行、表单与反馈用到的组件或变体，页面没有的不预建。再按原尺寸看局部、缩小看整体：

- **色彩有主次与呼应。** 主强调色和辅助对比色在关键操作、数据和图形里按职责呼应，不只给按钮换色。
- **数字有层级。** 主数值、比较说明和标签拉开字重与大小；关联指标靠对齐与分隔成组。
- **间距成节奏。** 页面边距、模块间距、模块内边距和同组信息四级取值，同组紧、跨组松。
- **导航与状态。** 当前项有稳定可见的标记，键盘焦点另有表达。普通状态保持安静，需要处置的异常更醒目；颜色不独自传递含义，也不要求所有状态都套胶囊。
- **按钮与输入。** 名称说明动作和对象，主次强调一致，输入标签与报错位置稳定。必要但暂不可用的动作说明原因，不为画面完整虚构可执行状态。
- **身份与图标。** 人物、组织与产品用清晰的头像、标志或缩略标识，并保留名称；身份图只用于识别对象。通用图标选一套成熟图标库，统一尺寸、线宽与文字对齐，不混用字符、Emoji 或不同画法；品牌标志保留真实形状与品牌色。

## 数据、列表与高频交互

- **表格与对齐**：每列明确负责识别、比较、状态或操作；决定是否处理这个对象所需的信息留在列表，详细证据进详情。名称留够宽度，可比较的数值用 `tabular-nums`，单位与精度统一；长名称、空值和异常值分得清。
- **指标与图表**：总量、趋势、分布和异常围绕当前判断组织；同一范围内的总数、拆分、筛选计数和明细互相对得上，静态原型做到直观自洽即可。样例数据包含正常、异常和边界记录，异常项同时给出原因、影响范围和具体对象的入口。
- **交互闭环**：打通“定位对象、查看判断依据、执行动作、看到结果”的真实操作序列。切换筛选、排序或开关详情时保留当前查询、滚动位置与焦点；操作反馈短促安静，局部更新，不让整页重新入场。

## 单个工作区组件

[组件](component.md) 的深度打磨用于单个控件、数据组件或操作面板时，用本节替代其中的表现性流程：

- 写清组件回答的问题、信息、操作、实际需要的状态和承载尺寸；沿用系统的文字、数字、颜色和控件，不补无关状态。
- 文字或数字能清楚回答问题时就够了，不要求实物主视觉、母题取色或遮字辨状态。图形确有判断价值时按工作区数据规则用；状态不只靠颜色表达。
- 已有组件与模式直接深化；获准改变且存在结构问题时才做内部候选。交互不默认加数字滚动、阻尼、吸附或独创控件。
- 取实际使用尺寸和必要的局部放大图，覆盖本次相关的状态与主要操作，按下面“自查与评审”交接，范围只限这个组件；不另做取色背景的作品图，除非用户需要展示图。

## 自查与评审

- **截图**：用 `shoot.mjs` 只取任务内的设备，手机 App 不补桌面壳；用 `--steps` 一次带出必要的一两个交互态，已经覆盖的流程不另开浏览器重走。工作台截视口图，不截整页。
- **局部核对**：除了整体空间，按原尺寸看选择器、指标组和身份列；页面没有横向滚动，不等于控件内部没有裁切或挤压。调过密度、字号或共享样式后，复看受影响的局部、焦点和长内容状态。
- **评审**：派独立评审时，在派发协议的模板后面补一句：`本次领域是产品工作区。先读 references/workspace-review.md，以它作为内容标准；任务类型、是否只读、是否打分与本轮范围如下：……。不要套用海报页的主角、字体性格、实物配色与装饰扣项。` 路径换成绝对路径。轮次、参考图交接和工作区评分的含义见 [评审循环与扩展派发](review-loop.md) 的“产品工作区评审”，默认的一轮不必读它。

## 并排对照，交给别人判断

用户提供或指定的可访问参考是质量基线，先分清借鉴与精准还原。借鉴时提取参考的身份素材、信息表达、主要对比与共同语言，记下本产品因任务不同必须改变的部分；不照搬参考的行业、品牌色或模块数量，也不凭品牌名臆测细节。

有可比较的参考图时，按相同视口、比例与状态，用 `shoot.mjs` 的 `--stitch` 并排交给评审者，差距写成具体位置与看得见的结果。比例不同才用 `--match-width` 或 `--scale`，比较局部才用 `--crop`，写法见 [工具](tools.md)；没拿到真实参考时按本文件验收，不宣称达到了某个品牌的完成度。
