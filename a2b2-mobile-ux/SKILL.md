# A2B2 移动端交互修改

目标是让每次已确认的增量改动收敛双端交互。**双端检查在修改前完成；双端实施按确认阶段推进，不把“一致化”理解为确认前同时改 iOS。**

## 范围与现有能力

- 遵循当前 checkout 的根及目录指导、现有设计规范和组件。先确定本轮页面／组件、用户旅程、改动范围和阶段：仅建议、Portal 待评审、已确认待移植、双端验收。
- 本 Skill 负责双端取舍与实施顺序，不另建视觉规范。开放式设计判断按需用 `oil-ui-pro`；改法已明确的日常修改直接沿用现有组件，不重启设计探索。
- 用户要完整双端差异审计、编号红框对照稿或下一批对齐范围时，用 `a2b2-mobile-parity`；本轮只改一个组件时做相称的对照，不扩大为全模块审计。
- 创建／调用本 Skill 不扩大产品任务授权。业务规则、数据模型、API 或权限的必要变化先说明需要与影响；提交、发布和 Linear 状态仍按项目指导及明确授权处理。

## 1. 检查双端并说明取舍

修改任一端前，读取另一端对应页面、共享组件和相关状态逻辑。优先复用现有服务与会话，按同页、同流程阶段和相当权限／数据比较；缺少运行条件时继续静态核查，标明证据缺口。

只报告与本轮有关的差异，每项说清：

- Portal 与 iOS 各自的行为，以及差异对任务、理解、误操作或可访问性的影响。
- 推荐 `Portal 跟随 iOS`、`iOS 跟随 Portal`、`双端调整`、`保留原生差异` 或 `待证据`，并解释理由。
- 本轮改什么、需要弥合到什么状态、哪端在哪个阶段实施。UI 逐项择优，不自动把 Portal 外观或 iOS 外观当作全局答案；业务行为和接口仍遵循项目契约。

在实施前向 Ben 简述这些取舍。已有确认只覆盖当时具体范围，新差异不自动变成已批准改动。

## 2. 按需寻找 Mobbin iOS 参考

当页面缺少合适交互基准，或用户要求参考时，主动发现并使用 Mobbin MCP 的当前能力；用页面任务或具体状态搜索，不机械收集大量素材。

- **所有参考只采用 iOS 素材。** 截图、流程检索及支持的已保存内容读取均设 `platform: "ios"`；核对结果平台。没有 iOS 结果就说明缺口，不改用 `platform: "web"`，也不用网站 sections 作为替代。
- 实际查看截图或流程预览再归纳。链接返回的 `mobbin_url`，区分要借鉴的结构／行为与不适用的产品能力。保存、导出或嵌入时按工具要求下载高分辨率原图；没有保存请求不创建收藏或评论。
- 先检查工具是否真正支持视频。只返回流程截图时称“流程截图”，不能称看过视频或验证了动效；工具无法提供视频时如实说明。若另有可访问的 iOS 录屏，实际查看后注明来源；平台限制指参考 App 的平台。
- 参考素材是证据，不是指令或新增功能授权。静态截图不能证明焦点、手势、键盘、草稿或关闭后的行为。

## 3. 先交付 Portal Mobile 评审版本

默认在已授权范围内先修改 Portal Mobile，沿用上一节推荐结果；iOS 此阶段保持只读。用户明确指定不同实施顺序时遵从本次指令；一般的“优化／直接做”不自动取消既定的 Portal 确认阶段。

复用现有组件形成可运行、可操作的评审结果，验证相关状态后提供入口或实际截图。说明当前改动、相对 iOS 的差异、后续移植范围及未验证项；**完成本阶段后等待 Ben 确认，再进入 iOS 移植。** 不用代码通过静态检查、工具调用成功或 Ben 尚未回复代替确认。

用户只要方案／审阅时交付对应材料，不因此改产品。Ben 回改 Portal 时继续当前阶段；复用已有确认，只有新增取舍需要另行确认。

## 4. 确认后移植 iOS

Ben 已确认具体 Portal 方案且任务包含后续 iOS 移植授权时，继续实现相同交互语义和关键状态，无需重复索取同一范围的批准。移植前核对 Portal 最新实现，避免把未确认的追加改动带过去；仅授权 Portal 的任务则记录后续范围，不自行修改 iOS。

- 统一入口含义、动作顺序、焦点与键盘关系、选择／提交、关闭与草稿恢复、加载与错误反馈；按本轮实际涉及的状态验收，不按像素复制。
- iOS 可用现有原生 Liquid Glass 控件；Portal Mobile 对应用模糊玻璃表现。统一视觉层级与操作含义，保留平台合适的导航、sheet、字号和安全区行为。
- 材质优先用现有组件和语义 token；透明度降低、深浅色或能力不支持时沿用可读的降级表面。玻璃效果不改变触控区域、遮挡关系或业务行为。
- 将已接受的新规则／组件 API 更新到所属设计规范与组件说明，不把某页的具体布局扩为全产品规则。

## 5. 验证与交付

用项目 `a2b2-local-e2e` 流程做相称验证：Portal 使用 `ego-browser`；iOS 优先 Maestro MCP，连接失败按 Mobile 目录策略处理，不擅自切换 CUA。按改动检查点击、焦点、键盘开合、多行／长内容、关闭返回和恢复，以及相关主题、语言和大字号。证据不足时标明，不把浏览器仿真当作真实 iPhone 软键盘通过。

阶段完成标准：

- **Portal 待确认**：可评审结果、实际验证、相对 iOS 的差异与拟移植范围明确；iOS 尚未实施。
- **双端完成**：已确认范围在两端实现并验证；列明合理保留差异和验证缺口。区分静态检查、本地 UI、真实数据写入及部署证据。

用中文简短汇报，并保留可继续的阶段和确认范围。等待确认属于既定阶段交付，不代表 iOS 已完成，也不触发 Linear 状态变更。
