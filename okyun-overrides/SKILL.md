# OK云覆写编辑

修改当前订阅实际绑定的脚本，保留用户未要求改变的设置。默认在客户端保存并自动重载。

## 用户约定

- **客户端启停由用户完成。代理不退出、关闭、杀进程、重启 OK云，也不通过关闭代理、TUN 或系统代理来触发重载。**关闭 OK云会切断代理与用户的网络连接。
- 用户已于 2026-10-29 验证：**在 OK云内编辑并保存脚本，会自动重载。**优先使用这条路径，不为普通规则修改安排重启。
- 离线写入偏好设置是备用路径：先完成修改、校验和应用命令，再交给用户退出、离线应用、重新打开。不要等待断网后的代理继续执行必要步骤。

## 保存位置

本机已核实 OK云 2.2.4、bundle ID `com.okyun.clash`，核心为 mihomo 的定制构建。

| 内容 | 位置与用途 |
| --- | --- |
| 实际脚本 | `~/Library/Preferences/com.okyun.clash.plist` 的 `flutter.config` 字符串，解析 JSON 后位于 `scripts[].content` |
| 订阅绑定 | 同一 JSON 的 `profiles[].overwrite.type == "script"`，通过 `overwrite.scriptOverwrite.scriptId` 指向脚本 |
| 生成配置 | `~/Library/Application Support/com.okyun.clash/OKYun/config.yaml`；用于核验，自动生成，不能作为编辑源 |
| 原订阅 | `~/Library/Application Support/com.okyun.clash/OKYun/profiles/<profile-id>.yaml`；订阅更新会覆盖，不能作为覆写编辑源 |

每次从 `currentProfileId` 找到当前订阅及其绑定脚本，不固定数组下标、脚本 ID 或历史规则数量。`Sparkle migration` 是此前创建的名称，不代替绑定检查。本地 `.js` 副本不被客户端自动监听。

## 工作流程

### 1. 导出当前源文件

用本 skill 的 `scripts/overrides.py export <绝对路径.js>` 导出当前绑定脚本。它只读取偏好设置，输出所选订阅、脚本 ID 和内容摘要，同时创建 `.baseline.json` 摘要记录。文件会以 UTF-8、私有权限创建；已有文件不会覆盖。

后续修改以此次导出的内容为基准。若当前订阅没有绑定脚本，先报告实际状态，再明确用户希望编辑哪个脚本；不要自动新建、切换订阅或改绑定。

### 2. 修改与校验

- 只实现用户指定的域名、目标策略、规则顺序或策略组变化。遇到未确定的出口选择，先查看现有组及用户已保存的选择。
- 保留订阅节点与凭据、脚本 ID、绑定、节点选择，以及未请求的 DNS、TUN、端口和账户设置。
- 规则自上而下匹配；把新增规则放在会截获它的宽泛规则和最终 `MATCH` 之前。检查目标策略组、`RULE-SET` 引用、组间引用与循环依赖。
- 本地 `type: file` 规则集需要实际文件；`inline` 内容和 MRS 格式应保留其语义。仅为编码或排版修改时，对比执行结果，确保规则、组和规则源一致。
- 保留可读的 UTF-8 中文和 emoji。**本版本的“Import from file”曾把 UTF-8 当作其他编码读取，产生真正的乱码。**优先在代码区粘贴源码；不要为绕过导入器将全部分组名称永久改成 `\uXXXX`。

在导出的同一个 `.js` 文件上编辑，保留相邻的 `.baseline.json`。运行 `scripts/overrides.py stage <修改后的绝对路径.js>`：先确认导出后客户端脚本和绑定未变，再完成 Node.js 语法检查，保存原稿、候选稿和内容摘要。它不写入客户端。Node.js 未安装时报告缺少语法检查，不自行安装软件。

语法检查不等于分流验证。阅读脚本后，仅对已确认是配置转换的代码进行受限执行；用现有 Node/YAML 工具将 `main(config)` 输出与当前配置比较，核对所有预期变化及无关字段。核心 `-t` 检查如需使用，应放在独立临时工作目录，避免占用正在运行的 `cache.db`；不要启动第二个代理监听器。未完成的检查如实说明。

### 3. 客户端保存并自动重载（首选）

通过可用的原生 UI 工具编辑已有脚本。已观察入口：主页右上角 Options → Override script；或设置 → Advanced configuration → Script。选中当前绑定脚本，再进入 Edit。

替换代码前、点击保存前，分别运行 `scripts/overrides.py check <stage目录>` 核对当前绑定和已保存源码仍与暂存原稿一致。发现用户期间改动、界面提示用户接管或存在用户未保存的编辑时，停止替换，先保留并合并这些改动；检查返回 `already_saved` 时跳过重复保存。

在代码区完整替换为已校验的 UTF-8 源码并保存，保留原脚本与绑定。确认编辑器实际显示中文、emoji，且保存后 `scripts[].content` 与候选稿一致。客户端保存会自动重载，无需重启或切换网络模式。

如果自动化无法可靠替换代码，停止反复尝试，将候选文件交给用户粘贴保存；也可以使用下面的离线备用流程。不要通过重启绕过界面问题。

### 4. 核验实际结果

- `scripts/overrides.py verify <stage目录>` 仅确认**已保存脚本和当前绑定**匹配候选稿，不代表运行中的核心已应用。
- 读取重新生成的 `config.yaml`，检查预期规则、策略组和规则源，并确认未请求的 DNS/TUN 等字段保持原样。客户端会规范化 provider 缓存路径，对比时区分路径规范化与规则语义变化。
- 结合客户端连接状态或用户确认，报告“已保存且重载、已核验”；若只有候选文件，报告“已准备，尚未应用”。不要把文件保存或语法通过当作全程成功。

## 离线备用流程（需要用户操作时读取）

运行中的客户端会保留偏好设置的内存副本。外部直接写 plist 不能保证即时生效，且可能被后续保存覆盖。`apply` 因此拒绝在 OK云主进程运行时写入。

1. 在线完成前面的修改和校验。`stage` 会打印完整的离线 `apply` 命令；先把这条具体命令交给用户。
2. 提醒用户：**完全退出 OK云（不是仅关窗口）→在本机终端执行该命令→自行重新打开 OK云。**命令完全离线，不管理应用进程；不要要求用户退出后再等待代理写入。
3. 代理不对真实偏好设置执行 `apply`，也不代替用户操作启停。用户恢复连接后，继续核验保存和生成配置。

`apply` 会重读最新偏好设置，核对订阅绑定与原稿摘要，备份偏好设置，只更新对应脚本的 `content`。若用户期间修改了脚本或切换了绑定，它会拒绝覆盖；重新导出并合并后再暂存。重复应用同一候选稿不会再次改写。

备份可能含订阅令牌、登录数据等敏感内容，保存在 `~/Library/Application Support/OKyun-migration/changes/` 下的私有目录中，不输出到聊天、提交到 Git 或上传。

交付时简述变更、校验结果、是否已经生效；只有需要用户操作时才提供退出和重新打开步骤。

维护本 skill 的辅助脚本时，运行 `python3 scripts/test_overrides.py`。测试使用隔离配置；macOS 写入测试仅使用临时测试域，不访问 OK云实际偏好设置。
